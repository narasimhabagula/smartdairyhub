# Smart Dairy Hub — Production Audit & Hardening (2026-09-13)

Read-only discovery first, then minimal production-safe fixes. No data, users, tables, auth
config or features were deleted. No secrets are printed here.

## Architecture

- Frontend: React 18 + Vite 5 + TypeScript + Tailwind, React Router, TanStack Query, i18next (12 languages), Capacitor shell.
- Backend: Lovable Cloud (Supabase) — Postgres with RLS, Auth (email + Google), Storage, 9 Edge Functions:
  `analyze-animal-health`, `auth-email-hook`, `chat-assistant`, `geo-resolve`, `kb-ingest`, `mcp`,
  `nearby-vets`, `place-order`, `translate`.
- AI: Lovable AI Gateway via server-side functions only. No AI keys in client code.

## Findings and status

| # | Severity | Finding | Location | Status |
|---|---|---|---|---|
| 1 | HIGH | Veterinary directory unreadable — no read policy or grants on `vet_doctors` / `vet_doctors_public`; users saw a raw `permission denied` message | DB + `src/pages/VetContacts.tsx` | Fixed: read policy for approved rows, column-level grants that exclude phone/email, view grant. Verified: directory request now returns 200 |
| 2 | MEDIUM | Uploads accepted any file type (SVG/script risk) and used user-supplied filenames | `Profile.tsx`, `IndustryPanel.tsx`, `SellerDashboard.tsx` | Fixed via `src/lib/uploads.ts`: raster/video MIME allowlist (no SVG), size caps, extension derived from MIME, UUID user-scoped paths |
| 3 | MEDIUM | No rate limiting on public/AI endpoints (paid Maps/AI quota abuse) | 5 Edge Functions | Fixed: durable per-caller limits in `public.api_rate_limits` (service-role only). Verified: 80 concurrent calls → 32 allowed, 48 rejected with 429 |
| 4 | MEDIUM | Raw database/network errors surfaced to users | multiple pages | Fixed via `src/lib/errors.ts` (`friendlyError`); details logged in dev only |
| 5 | LOW | Disease-detection accepted any declared image MIME | `analyze-animal-health` | Fixed: JPEG/PNG/WebP only |
| 6 | INFO | Two anonymous `SECURITY DEFINER` functions (`get_top_help_faqs`, `get_top_help_searches`) | DB | Accepted: aggregate help-centre metrics, no PII, capped result size |
| 7 | INFO | Wildcard CORS on public functions | Edge Functions | Accepted: endpoints are intentionally public and now rate limited |

Verified as already correct: RLS enabled with policies on every public table; roles held in a separate
`user_roles` table with an escalation-blocking trigger; PII (phones/emails) released only through
security-definer RPCs with ownership checks; order totals computed server-side; service-role key used
only inside Edge Functions, never in `src/`; chat assistant requires a valid JWT; `dangerouslySetInnerHTML`
only inside the chart primitive; AI health output carries a veterinary disclaimer.

## Testing performed

- Typecheck: pass. Unit tests: 2 files / 8 tests pass. Build: `build OK`.
- Browser smoke (1280px): `/`, `/marketplace?category=medicine`, `/vet-contacts`, `/milk-rates`,
  `/disease-detection`, `/schemes`, `/cattle-market`, `/help`, `/dashboard`, `/profile` all render,
  zero horizontal overflow, no failing HTTP requests after the fixes.
- Marketplace deep links verified: `?category=medicine` selects the Medical Store tab.
- Rate limiting verified under concurrency (see finding 3).
- Console output contains only React dev warnings (ref forwarding, unknown prop) — no runtime errors.

## Remaining risks / needs human action

1. Google sign-in audience mismatch: if custom Google credentials are set in backend Authentication
   Settings → Google, the client ID must match the one issuing the token, or clear them to use the
   built-in Google login. Not fixable in app code.
2. Google Maps API key restrictions and production security headers (CSP, HSTS) live in hosting/provider
   configuration and were not verifiable from the code.
3. Lint debt: 239 ESLint problems, overwhelmingly pre-existing `no-explicit-any`. Not mass-refactored to
   avoid unrelated regressions.
4. Rate limits are a quota brake, not a security boundary; authorization remains enforced in SQL.

No claim is made that the application is fully penetration-tested or "100% secure".
